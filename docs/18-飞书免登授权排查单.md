# 飞书免登 20029 事故复盘（2026-11-17）

> 应用：`cli_aa7f2e3902385d0e`（小绩，自建应用）
> 现象：点击「飞书登录」→ 飞书授权页报 `重定向 URL 有误，错误码：20029`，授权无法完成
> 结果：**已解决，真机免登跑通**
> 价值：**20029 的报错文案是误导性的** —— 真正的原因有三个，且没有一个是「后台 URL 没配」

---

## 一、为什么 20029 这么难查

飞书对 20029 的官方说明只有两条：

> - 当前应用与配置重定向 URL 的应用不匹配
> - 应用未配置重定向 URL

但实际情况是：**下面三个问题任意一个存在，都会报同一个 20029**。
飞书不告诉你缺什么参数，只告诉你「重定向 URL 有误」——
让人反复去核对后台白名单（而后台是对的）。

> ⚠️ **排查纪律**：看到 20029，**不要只查后台**。
> 先按本文第三节的三个原因逐一排掉，再去动后台配置。

---

## 二、真实原因（按发现顺序）

### 原因 1：授权 URL 的参数名写错了（代码 bug）

官方文档（[获取授权码](https://open.feishu.cn/document/authentication-management/access-token/obtain-oauth-code)）要求：

| 参数 | 必填 | 正确值 |
|---|---|---|
| `client_id` | ✅ | 应用的 App ID |
| `response_type` | ✅ | 固定 `code` |
| `redirect_uri` | ✅ | URL 编码后的回调地址 |

原代码写的是：

```python
params = {
    "app_id": settings.feishu_app_id,   # ❌ 应为 client_id
    "redirect_uri": redirect_uri,
    "state": state,
}                                        # ❌ 缺 response_type=code
```

**症状极具误导性**：参数缺失时飞书不报「缺少参数」，
而是渲染一个「重定向 URL 有误 / 20029」的错误页 ——
让人以为后台白名单没配。

**修法**：

```python
params = {
    "client_id": settings.feishu_app_id,
    "response_type": "code",
    "redirect_uri": redirect_uri,
    "state": state,
}
```

### 原因 2：后台确实没配重定向 URL（配置漏项）

用官方 API 直接读应用配置，可以**不靠肉眼判断**：

```http
GET /open-apis/application/v6/applications/{app_id}?lang=zh_cn
Authorization: Bearer {tenant_access_token}
```

> ⚠️ `lang` 是**必填**查询参数 —— 漏了会返回 `99992402 field validation failed`，
> 看起来像「接口不存在」，其实是参数没给全。

响应里最关键的两个字段：

```json
{
  "app": {
    "redirect_urls": ["http://localhost:5180/feishu/callback"],
    "pc_default_ability": "bot"
  }
}
```

修复前 `redirect_urls` 是 **空数组** —— 这就是 20029 的直接原因。

**配置位置**：开发者后台 → 应用详情 → **开发配置 → 安全设置 → 重定向 URL**

> ⚠️⚠️ **不要配在「应用能力 → 网页应用」里**。
> 那里配的是「桌面端主页 / 移动端主页」= 员工点开飞书里「小绩」图标后打开的页面，
> **不是 OAuth 授权白名单**。配在那里完全无效 —— 这是本次最大的弯路。

### 原因 3：查用户信息用了错误的接口（代码 bug）

换到 token 之后，下一步是拿用户身份。原来的实现是：

```python
info = self.client.get_user_info(user_access_token, token_data.get("user_id", ""))
# → GET /contact/v3/users/{user_id}?user_id_type=user_id
```

但 **`/authen/v2/oauth/token` 的响应里根本没有 `user_id` 字段**。
官方字段只有：

```
access_token / refresh_token / expires_in / scope / token_type
```

⇒ `user_id` 恒为空 ⇒ 通讯录接口路径残缺 ⇒ 抛「缺少 user_id」⇒ 502。

**修法**：改用官方给登录用户准备的接口 —— **不需要 user_id**，
手上的 token 本身就代表「这个人」，这正是免登的语义：

```http
GET /open-apis/authen/v1/user_info
Authorization: Bearer {user_access_token}
```

⚠️ 响应结构也不同：`data` 是**扁平**的用户信息，**没有多包一层 `user`」。
代码需兼容两种形状，否则响应结构一变，免登又挂。

## 三、排查顺序（下次照这个走）

```
看到 20029
   │
   ├─ ① 先查自己的授权 URL 参数对不对
   │     client_id？response_type=code？redirect_uri 已 URL 编码？
   │     ← 本次的原因 1。**成本最低，先做**
   │
   ├─ ② 用 API 读后台配置，别靠肉眼
   │     GET /open-apis/application/v6/applications/{app_id}?lang=zh_cn
   │     看 redirect_urls 是否含你要的地址（逐字比较）
   │     ← 本次的原因 2
   │
   └─ ③ 302 回调成功但后续 502？
         看换 token 是否 200、响应里有 user_id 吗
         ← 本次的原因 3
```

### 怎么确认「后台到底配了啥」

**别用眼睛数**。直接读 API：

```python
import httpx
from app.core.config import settings

tok = httpx.post(
    "https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal",
    json={"app_id": settings.feishu_app_id, "app_secret": settings.feishu_app_secret},
    timeout=20,
).json()["tenant_access_token"]

app = httpx.get(
    f"https://open.feishu.cn/open-apis/application/v6/applications/{settings.feishu_app_id}",
    headers={"Authorization": f"Bearer {tok}"},
    params={"lang": "zh_cn"},          # ← 必填！
    timeout=20,
).json()["data"]["app"]

print(app["redirect_urls"])            # 后台实际配的白名单
print(app["pc_default_ability"])       # 网页应用能力是否启用
```

## 四、留个记录：本次的三个「坑」

| # | 坑 | 教训 |
|---|---|---|
| **P1** | 参数名写成 `app_id`，飞书报「重定向 URL 有误」 | **报错文案不可信**。参数错误伪装成配置错误 |
| **P2** | 「重定向 URL」配到了「应用能力 → 网页应用」 | 同名不同义。飞书后台有多个 URL 配置位，OAuth 白名单只有一个 |
| **P3** | 后端绑 `127.0.0.1`，Vite 代理走 `localhost`（IPv6 `::1`）→ `ECONNREFUSED` | 本地 IPv4/IPv6 混用。代理报 `ECONNREFUSED` 时**先查绑定地址** |
