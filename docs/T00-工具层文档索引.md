### 3.2 开工前必须知道的两个既有 Bug

工具层要走的路上有**现在就在的洞**，Step 4 必须先修：

| Bug | 位置 | 症状 |
|---|---|---|
| **B1** | `main.py:1251` | `check_can_view_score(current_user, ...)` 传 `Employee` 对象，签名要 `user_id: str` → 主管查下属是坏的 |
| **B2** | `main.py:1263` | `peer_performance_distribution` 分支**无任何权限校验** → 任何登录用户可查任意部门聚合 |

> ⚠️ **B2 尤其重要**：`get_department_stats` 工具干的正是这件事。
> 不拦 = 给已有漏洞加了个更好用的入口。

### 3.3 开工前的环境准备

```powershell
# backend/.env 新增两行
AGENT_TOOL_SECRET=<64位随机hex>        # python -c "import secrets; print(secrets.token_hex(32))"
AGENT_TOOL_TOKEN_TTL_SECONDS=300

# agent-service/.env 新增一行（Step 4 才需要）
AGENT_TOOL_BASE_URL=http://127.0.0.1:8000
```

> ⚠️ `AGENT_TOOL_SECRET` 有 **32 位长度下限 + 弱密钥黑名单**校验（Step 1.1），
> **不配置时 backend 启动即失败** —— 这是刻意的「宁可不提供工具能力，也不要裸奔」。
