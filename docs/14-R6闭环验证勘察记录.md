## 🔴 BUG-R6-01：员工计划/成果「列表页」接口 404（前端页面不可用）

**现象**
前端 `api/planning.ts` 的三个列表接口，经 Vite 代理 `/api → /v1` 后，
实际请求 `/v1/planning/month-plans`、`/v1/planning/day-plans`、`/v1/planning/results`，
这三个路径**均返回 404**。

**实测**
```
GET /v1/planning/stats        -> 200   （真实现，仅 stats 有）
GET /v1/planning/month-plans  -> 404
GET /v1/planning/day-plans    -> 404
GET /v1/planning/results      -> 404
```

**影响页面**（都调用了上述接口）
- `views/employee/EmployeeMonthPlanListRefactored.vue` → `listMonthPlansApi`
- `views/employee/EmployeeDayPlanList.vue` → `listDayPlansApi`
- `views/employee/EmployeeResultList.vue` → `listResultsApi`
- `views/employee/EmployeeMonthPlanEdit.vue` → `listMonthPlansApi`

**根因**
后端 `routes/planning.py` 只实现了 `/stats`；`routes/employee_plans.py` 与
`routes/employee_result.py` 只有「草稿/提交/详情」类端点，
**没有任何列表端点**（如 `GET /v1/employee/month-plans`）。

> 佐证：`main.py` 里有一个 mock 版 `GET /planning/month-plans`（无 `/v1` 前缀），
> 返回硬编码样例数据。它是**死代码** —— 前端永远命中不到（代理会加 `/v1`），
> 但它掩盖了「列表接口根本不存在」这个事实。

**待修**
补 `GET /v1/employee/month-plans`、`/day-plans`、`/results` 三个列表端点
（或改前端指向已有端点）。→ 归入 R6 待完善清单。

## 🟡 观察项 R17：92 条同步错误 = 部门外键被 rollback 连带撤销

**根因（已用最小复现脚本验证）**
`organization_sync.py` 的 `_upsert_department()` 只调 `self.db.flush()`
（发 SQL 但**不 commit**）；随后 `_sync_employees()` 里某条员工插入异常时
执行 `self.db.rollback()` —— 这一 rollback 把**尚未提交的部门插入一并撤销**，
于是后续所有员工的 `department_id` 外键全部失败。

最小复现输出：
```
rollback 后 department 行数: 0     ← 部门被连带撤销
rollback 后 employee 行数: 0
E3 插入: *** 失败 *** IntegrityError: FOREIGN KEY constraint failed
```

**佐证**
- 失败批次 `ORG-20261114-d8fe0dfc5c`：`departments_synced=30`、
  `employees_synced=0`、`employees_failed=92`
- 下一批次 `ORG-20261114-e75a1f6d26`（full）`employees_synced=92` 成功
- 92 条错误消息全部是 `FOREIGN KEY constraint failed`，
  且 `error_category` 为 `None`（这些行早于 0010 迁移，未回填分类）

**待修**
`organization_sync.py` 的事务边界：部门写入应在员工写入前**独立提交**，
或改用 savepoint 隔离单条失败。→ 归入 P1 待办（用户已列为 P1 任务）。
