# ★ 部门工作量板块（2026-11-25）

> **一句话**：按**飞书同步过来的真实组织架构**，给每个部门开通「部门工作量」板块，
> 让各部门**能开始填东西**；**各岗位填什么指标后续再定**。

---

## 一、为什么要有这个板块

### 1.1 之前的状况

```
department_module 表：只有 1 行 —— 短视频 → pan_workload
⇒ 只有短视频能填东西，其它 25 个部门打开就是空的
```

### 1.2 关键约束

⚠️ **不能把剪辑板块直接开给所有部门**：

| 板块 | 数据来源 | 谁能用 |
|---|---|---|
| `pan_workload`（剪辑工作量） | **百度网盘**自动采集成片条数 | 只有短视频（网盘是短视频的） |
| `dept_workload`（部门工作量） | **纯人工填报** | 任何部门 |

⇒ 新增 `dept_workload` 通用板块，`pan_workload` 保持独立。

---

## 二、架构

### 2.1 三层模型（不变）

| 维度 | 回答的问题 | 载体 |
|---|---|---|
| **板块** | 这个部门有没有这个业务 | `department_module` |
| **岗位角色** | 这个人在这个业务里是填/审/不参与 | `pan_workload_policy` |
| **指标** | 具体填哪几个 | `pan_workload_policy.metric_codes` |

### 2.2 为什么是**一个**通用板块而不是 26 个

各部门的差异**只在「填什么指标」**，那本来就由 `pan_workload_policy` 承载。
⇒ 26 个板块 = 26 份几乎一样的路由/页面/前端菜单。
⇒ **一个通用板块 + 岗位口径** = 隔离照旧，零代码重复。

---

## 三、⚠️ 这次踩到并修掉的坑

### 3.1 默认指标跨板块泄漏（**最严重**）

`pan_workload_policy` 历史上「没配指标 ⇒ 回退默认指标」，
而默认指标**写死成视频指标**（普通视频/OOTD/智能体）。

⇒ 开了新板块后，**仓储部的分拣员会收到「今天剪了几条视频」的卡片**。

**修复**（`pan_workload_policy.py`）：

```python
def default_codes_for_role(role, module_code=PAN_WORKLOAD_MODULE):
    # ⚠️ 非剪辑板块 ⇒ 没有默认指标（指标待定）
    if module_code != PAN_WORKLOAD_MODULE:
        return ()
    ...
```

⇒ **只有剪辑板块**才有视频默认；其它板块「没配指标」= **指标待定**（空）。

### 3.2 数据范围判定复制两份

新增通用板块时若**照抄**一份范围判定 ⇒ 改一处忘一处 ⇒ **权限漏洞**。

**修复**：抽到 `services/pan_workload_scope.scope_employee_ids`，
两个 router 都调它，并加测试锁死（`test_两个router都调用共享服务`）。

### 3.3 前端路径带 `/v1` ⇒ 404

vite 代理把 `/api/xxx` 重写成 `/v1/xxx`
⇒ 前端写 `/v1/dept/workload/...` 会变成 `/v1/v1/...`。
⇒ 正确写法：`const BASE = '/dept/workload'`（与 `panWorkload.ts` 同口径）。

**这个 bug 是 CI 的 API 契约校验抓出来的**（不是靠眼睛看出来的）。

## 四、按飞书真实架构开通了什么

### 4.1 业务域划分

| 业务域 | 开通的部门 | 人数 |
|---|---|---|
| 仓储物流 | 仓储部 → 广州分部(包装小组/发货分拣打包组→晚班发货小组/售后拆件)、湖北园区 | 25 |
| 客服售后 | 客服部 → 客服小组、售后小组 | 11 |
| 电商运营 | 运营中心 → 商务部、直播部、运营部→抖店小组/拼多多&淘宝小组/跨境部 | 15 |
| 商品供应链 | 商品中心 → 买手部、版房→纸样组/车板组；生产部、采购部 | 14 |
| 职能支持 | AI技术部、人事行政部、财务部、总经办 | 8 |
| **短视频**（**不开**） | —— | 已有 `pan_workload` |

⚠️ **短视频为什么排除**
它挂在「运营中心」下 ⇒ 开通父部门会**连带继承**给它
⇒ 而它已有专属板块（含网盘采集）⇒ 两个入口 ⇒ 困惑。
⇒ 故「电商运营」域**逐个子部门开通**，短视频自然被排除。

### 4.2 岗位角色规则

| 规则 | 例子 |
|---|---|
| 岗位名含「主管/经理/组长/总监/总经理/负责人」 ⇒ **reviewer** | 仓库主管、商务主管、买手主管、人事主管、总经理 |
| 岗位名含「主播」 ⇒ **none**（不参与） | 短视频主播、直播部主播 |
| 没岗位 ⇒ **none** | 湖北园区 2 人、售后小组 1 人 |
| 其它 ⇒ **reporter** | 分拣员、客服、剪辑、买手、FDE… |

**开通过 20 个部门、37 条岗位口径。**

## 五、怎么用

### 5.1 运维命令

```powershell
# ① 体检（只读，不写库）
python backend/scripts/seed_department_workload.py --dry-run

# ② 实际开通
python backend/scripts/seed_department_workload.py --confirm
```

⚠️ 脚本**从库里读飞书同步过来的部门树**，不写死部门清单
⇒ 飞书新增部门后重跑即可。

### 5.2 配置指标（**后续业务定**）

⚠️ **当前指标是空的** ⇒ 卡片不出现填报项，页面显示「填报指标待业务确认」。

配置方式：往 `pan_workload_policy.metric_codes` 填指标码（逗号分隔）。

⚠️ **指标必须先在 `daily_metric_specs.py` 注册**（否则前端拿不到标签与量纲）。

⚠️ **命名必须带业务前缀**（如 `warehouse_pick_count`）：
真实库里 HR 已占用 `retention_rate`（员工留任率）
⇒ 新指标也叫 `retention_rate` ⇒ **同名 ⇒ 同一条数据 ⇒ 互相覆写**。

### 5.3 用户看到什么

| 场景 | 界面 |
|---|---|
| 仓储部分拣员 | 侧边栏「部门工作量」→ 页面显示「填报指标待业务确认」 |
| 短视频剪辑 | 侧边栏「剪辑工作量」（**没有**「部门工作量」） |
| 短视频主播 | **没有**任何板块入口 |
| HR / 管理员 | 两个板块都看到（要配置、要核对全局数据） |
