## 一、背景与目标

### 1.1 现状

当前智能体服务（`agent-service`）是六个无状态的单次函数，全部继承 `BaseAgent`，执行路径固定为：

```
build_payload → redact → 调一次模型 → Schema 校验 → 失败重试 → 降级
```

这套结构没有工具调用能力，没有多步推理循环，没有跨步骤状态。所有数据由业务后端（L2）在调用前一次性准备好，通过 `POST /v1/agent/draft` 传递。

### 1.2 为什么现在加工具层

加工具层不是为了让它看起来更像 agent，而是因为下面两类场景用"一次性塞数据"的方式做不好：

1. **数据范围不确定**。比如问答助手，用户问"我这个月哪些指标掉了"，后端事先不知道要查哪几个指标、查几个月，必须先查目录再取数。
2. **多步任务，后一步依赖前一步结果**。比如计划生成助手，要先查员工历史计划，再查部门验收标准，才能生成像样的建议。

对于已经拿到全部数据的场景（比如评分草稿），加工具没有收益，只会增加延迟和不确定性。

### 1.3 本方案目标

1. 给智能体服务增加只读工具调用能力。
2. 守住现有 L2 与 L3 的隔离边界，agent 不直接接触数据库和飞书。
3. 保证工具调用的权限、脱敏、可观测、可降级。
4. 分阶段落地，第一步只覆盖问答和计划生成两个场景。

### 1.4 非目标

1. 不让 agent 产生分数、改状态、做审批。这违反 `docs/01` 的四条不可破原则。
2. 不提供写工具。工具层只读。
3. 不重写已经跑通的 `/v1/agent/draft` 流水线。

## 二、设计边界（五条，不可破）

| 编号 | 原则 | 代码落点 |
|---|---|---|
| B1 | agent 不直接访问数据库和飞书 | 工具通过 HTTP 调 L2 的只读网关 |
| B2 | 工具只读 | `ToolRegistry.register()` 拒绝 `read_only=False` |
| B3 | 令牌绑定员工 | 工具参数不接受 `employee_id`，强制用令牌内的值 |
| B4 | 工具失败不阻断主流程 | 错误作为工具结果返回给模型，收敛不了就走降级 |
| B5 | 一切调用留痕 | 每次工具调用写入 `AiTrace`，记录工具名、参数摘要、耗时、结果状态 |

这五条是硬约束，开发时用代码实现，不靠约定。

## 三、适用性判断：哪些 agent 需要工具

| 智能体 | 是否需要工具 | 原因 |
|---|---|---|
| 评分草稿 `rating` / `comment` | 不需要 | 后端已把全部指标和证据装进 payload，加工具无收益 |
| 证据校验 `evidence` | 不需要 | 输入就是一段文本，不需要查外部数据 |
| 问答 `qa` | 需要 | 需要先查数据目录，再决定取哪些数据 |
| 计划生成助手（`employee_ai`） | 需要 | 需要历史计划、验收标准、部门规则等多步上下文 |
| 填报辅导 `fill_coach` | 可选 | 需要解释指标口径时才查配置，优先级低 |
| 校准 `calibration` | 可选 | 需要聚合统计，但可以一次性预取 |

**第一批只做 `qa` 和计划生成助手。** draft 那条链路保持不动。

## 四、架构选型

### 4.1 三个方案对比

| 方案 | 做法 | 优点 | 问题 | 结论 |
|---|---|---|---|---|
| A 后端工具网关 | agent-service 通过 HTTP 调 backend 只读端点 | 守住隔离边界，权限和脱敏复用现有能力 | 多一跳网络，后端需新增端点 | **推荐** |
| B agent 直连只读库 | agent-service 拿只读数据库连接 | 延迟低，实现简单 | 打破隔离，PII 和权限要在 agent 侧重做 | 不采用 |
| C 预取上下文包 | L2 提前打包可能用到的数据 | 零新增基础设施 | agent 无法按需扩展，payload 容易爆炸 | 仅作兜底 |

### 4.2 推荐方案 A 的数据流

```
agent-service                                  backend (L2)
    │  ① 模型决定调用 get_metric_values
    │  ── POST /v1/agent-tools/get_metric_values ──▶
    │     Header: 短时服务令牌（绑定员工 / 任务 / 工具白名单）
    │                                            ② 校验令牌与权限
    │                                            ③ 查库 + 脱敏 + k 匿名
    │  ◀────── {"code": 0, "data": ...} ───────────
    │  ④ 工具结果作为 tool 消息喂回模型
    │  ⑤ 模型给出最终答案或继续调用
```

关键点：agent 拿到的是 L2 已按权限过滤、已脱敏的数据。agent 不知道数据库结构，也看不到飞书 ID 和原始 PII。

### 4.3 与现有代码的关系

| 现有文件 | 改动 |
|---|---|
| `agent-service/app/base.py` | 新增 `complete_with_tools` 协议方法，新增 `ToolUsingAgent` |
| `agent-service/app/main.py` | 新增 `GET /v1/agent/tools`（可选，便于排障） |
| `agent-service/app/tools.py` | 新建，放 `ToolSpec`、`ToolRegistry`、HTTP handler |
| `backend/app/routes/agent_tools.py` | 新建，只读工具网关 |
| `backend/app/services/review_service.py` | 调用 agent 时签发工具令牌 |
| `backend/app/services/ai_service.py` | 不需要改，工具调用日志走 `AiTrace` 或新表 |

## 五、工具契约

### 5.1 ToolSpec

```python
# agent-service/app/tools.py
from dataclasses import dataclass
from typing import Any, Callable


@dataclass
class ToolSpec:
    """一个可被模型调用的只读工具。"""

    name: str
    description: str
    parameters: dict[str, Any]      # JSON Schema
    handler: Callable[[dict[str, Any]], dict[str, Any]]
    read_only: bool = True
    timeout_s: float = 8.0
    max_chars: int = 8000           # 结果截断上限
```

### 5.2 ToolRegistry

```python
class ToolRegistry:
    """工具注册表。负责白名单过滤、调用分发、结果截断。"""

    def __init__(self) -> None:
        self._tools: dict[str, ToolSpec] = {}

    def register(self, spec: ToolSpec) -> None:
        if not spec.read_only:
            raise ValueError("绩效域不允许写工具")
        self._tools[spec.name] = spec

    def schema(self, allow: set[str]) -> list[dict[str, Any]]:
        """转成模型可见的 function 定义，只暴露白名单内的工具。"""
        return [
            {
                "type": "function",
                "function": {
                    "name": t.name,
                    "description": t.description,
                    "parameters": t.parameters,
                },
            }
            for name, t in self._tools.items()
            if name in allow
        ]

    def call(
        self, name: str, args: dict[str, Any], allow: set[str]
    ) -> tuple[dict[str, Any] | None, str | None]:
        """执行工具。返回 (数据, 错误)。错误不是异常，交给模型处理。"""
        spec = self._tools.get(name)
        if spec is None:
            return None, f"未知工具 {name}"
        if name not in allow:
            return None, f"该智能体无权调用工具 {name}"
        try:
            data = spec.handler(args)
        except Exception as exc:
            return None, f"工具 {name} 执行失败：{exc}"

        text = json.dumps(data, ensure_ascii=False)
        if len(text) > spec.max_chars:
            data = {"truncated": True, "preview": text[: spec.max_chars]}
        return data, None
```

### 5.3 HTTP handler

```python
def http_handler(base_url: str, token: str, name: str) -> Callable:
    """工具的标准实现：调 L2 的只读网关。"""

    def handler(args: dict[str, Any]) -> dict[str, Any]:
        with httpx.Client(timeout=8.0) as c:
            r = c.post(
                f"{base_url.rstrip('/')}/v1/agent-tools/{name}",
                json=args,
                headers={"Authorization": f"Bearer {token}"},
            )
            r.raise_for_status()
            body = r.json()
            if body.get("code") != 0:
                raise RuntimeError(body.get("message") or "工具返回错误")
            return body.get("data") or {}

    return handler
```

### 5.4 模型协议扩展

现有 `ModelClient.complete()` 返回 `(dict, error)`，保持不动。新增一个可选方法：

```python
class Completion(BaseModel):
    content: dict[str, Any] | None = None
    tool_calls: list[dict[str, Any]] = []   # {id, name, arguments}


class ModelClient(Protocol):
    model: str

    def complete(self, system: str, user: str, *, schema=None):
        ...

    def complete_with_tools(
        self, messages: list[dict[str, Any]], tools: list[dict[str, Any]]
    ) -> tuple[Completion | None, str | None]:
        """带工具的补全。不支持工具的客户端返回 (None, '不支持工具调用')。"""
        ...
```

`EchoModelClient` 也要实现这个方法，用于测试。建议给它加一个确定性模式：第一次返回某个预设的 `tool_call`，第二次返回最终结果，专门验证循环和降级。

## 六、推理循环

### 6.1 ToolUsingAgent

```python
class ToolUsingAgent(BaseAgent):
    """带工具调用能力的智能体基类。

    子类只需声明 allowed_tools 和 max_steps，其余由基类负责。
    """

    allowed_tools: set[str] = set()
    max_steps: int = 5
    max_tool_calls: int = 8

    def run_with_tools(self, registry: ToolRegistry, **kwargs) -> AgentResult:
        payload = self.build_payload(**kwargs)
        red = redact(payload)

        messages = [
            {"role": "system", "content": self.system_prompt()},
            {"role": "user", "content": json.dumps(red.output, ensure_ascii=False)},
        ]
        tools = registry.schema(self.allowed_tools)
        used = 0

        for step in range(self.max_steps + 1):
            resp, err = self.client.complete_with_tools(messages, tools)
            if err or resp is None:
                break

            if resp.tool_calls:
                if used + len(resp.tool_calls) > self.max_tool_calls:
                    break
                messages.append(
                    {"role": "assistant", "content": None, "tool_calls": resp.tool_calls}
                )
                for call in resp.tool_calls:
                    used += 1
                    data, call_err = registry.call(
                        call["name"], call.get("arguments") or {}, self.allowed_tools
                    )
                    messages.append(
                        {
                            "role": "tool",
                            "tool_call_id": call["id"],
                            "content": json.dumps(
                                {"ok": call_err is None, "data": data, "error": call_err},
                                ensure_ascii=False,
                            ),
                        }
                    )
                    self._trace_tool_call(call, data, call_err)
                continue

            try:
                validated = self.output_model.model_validate(resp.content or {})
            except ValidationError:
                break

            result = AgentResult(
                agent=self.name,
                data=validated.model_dump(),
                degraded=False,
                model=self.client.model,
                prompt_version=self.prompt_version,
                input_hash=hash_input(red.output),
            )
            self._trace(result, status="ok")
            return result

        # 超步数、超调用次数、模型失败，统一降级
        result = AgentResult(
            agent=self.name,
            data=self.fallback(payload, "工具循环未收敛"),
            degraded=True,
            model=self.client.model,
        )
        self._trace(result, status="degraded")
        return result
```

### 6.2 上限策略

| 参数 | 建议值 | 作用 |
|---|---|---|
| `max_steps` | 5 | 模型最多推理 5 轮，防止绕圈 |
| `max_tool_calls` | 8 | 单次任务最多调 8 次工具 |
| 单工具超时 | 8 秒 | 防止一个工具拖死整条请求 |
| 结果截断 | 8000 字符 | 防止上下文被单个工具结果撑爆 |
| 整体超时 | 30 秒 | 与现有 `review_service.AgentClient` 的 30 秒保持一致 |

### 6.3 失败处理

1. 工具返回错误：作为 `{"ok": false, "error": ...}` 喂回模型，让它换个方式重试。
2. 模型连续失败或超步数：走 `fallback()` 降级模板。
3. 整个 agent-service 不可用：由 L2 的 `generate_draft` 的 try/except 兜底，现有逻辑已经支持。

## 七、后端工具网关

### 7.1 路由

新建 `backend/app/routes/agent_tools.py`：

```python
router = APIRouter(prefix="/v1/agent-tools", tags=["agent-tools"])


@dataclass
class AgentToolContext:
    employee_id: str
    task_id: str
    allow: set[str]


@router.post("/get_metric_values")
def get_metric_values(
    req: MetricQuery,
    ctx: AgentToolContext = Depends(agent_ctx),
    db: Session = Depends(get_db),
):
    _assert_tool_allowed(ctx, "get_metric_values")
    rows = _load_metrics(db, ctx.employee_id, req.period)
    return {"code": 0, "data": _redact(rows)}
```

注意：查询参数里**不接受** `employee_id`，员工身份一律取令牌里的值。这是防止 agent 查别人的第一道闸。

### 7.2 服务令牌

由 L2 在调用 agent-service 时签发，短时有效，范围窄：

```python
def issue_agent_tool_token(
    employee_id: str,
    task_id: str,
    allow: list[str],
    ttl: int = 300,
) -> str:
    payload = {
        "sub": employee_id,
        "task": task_id,
        "allow": allow,
        "exp": int(time.time()) + ttl,
    }
    encoded = base64.urlsafe_b64encode(
        json.dumps(payload, separators=(",", ":"), sort_keys=True).encode()
    ).decode().rstrip("=")
    sig = hmac.new(settings.agent_tool_secret.encode(), encoded.encode(), hashlib.sha256).hexdigest()
    return f"{encoded}.{sig}"
```

为什么不让 agent 直接带用户 token：那样 agent 能以员工身份访问任意接口，等于把整个后端暴露给模型。短时、窄范围的服务令牌更稳。

### 7.3 权限与脱敏

1. 令牌校验签名、过期时间、工具白名单。
2. 数据查询复用现有 `access_control` 的判定，身份取令牌里的员工。
3. 返回前统一走脱敏：姓名转别名，手机号、身份证、邮箱掩码。
4. 聚合类数据做 k 匿名：人数少于 5 不返回平均值，复用 `qa_service` 里已有逻辑。

### 8.1 第一批工具

### 8.2 不提供的工具

| 类别 | 原因 |
|---|---|
| 写指标值 | 会突破"模型不产生数字" |
| 改计划状态 | 状态机只能由 L2 和人工驱动 |
| 提交审批 | 审批是人的动作 |
| 查询原始 PII | 违反脱敏要求 |
| 跨员工明细查询 | 权限无法在单次调用内收敛 |

## 九、安全红线

开发时逐条对照，缺一条都不算完成：

- [ ] 注册表拒绝写工具（`read_only=False` 直接抛错）
- [ ] 每个 agent 声明 `allowed_tools`，`schema()` 和 `call()` 双重检查
- [ ] 工具参数不接受 `employee_id`，强制用令牌值
- [ ] 令牌短时有效（不超过 5 分钟）、绑定任务、绑定工具白名单
- [ ] `max_steps` 和 `max_tool_calls` 生效
- [ ] 单工具超时和结果截断生效
- [ ] 工具返回数据在 L2 侧脱敏
- [ ] 聚合数据做 k 匿名
- [ ] 每次工具调用写审计日志，记录工具名、参数摘要、耗时、结果状态
- [ ] 工具失败不抛异常到 agent-service 外层，走降级

## 十、可观测性与评测

### 10.1 审计字段

每次工具调用写入一条记录，字段建议：

| 字段 | 说明 |
|---|---|
| `trace_id` | 一次 agent 运行 |
| `agent` | 哪个智能体 |
| `step` | 第几轮 |
| `tool` | 工具名 |
| `args_hash` | 参数摘要，不存原文 |
| `ok` | 是否成功 |
| `latency_ms` | 耗时 |
| `error` | 失败原因（脱敏） |

现有 `agent-service` 的 `_trace` 已经能接 tracer，扩展一下字段即可。

### 10.2 评测集

工具层接真模型后输出不确定，必须先有评测集再谈调优。

建议第一批准备 20 到 30 条真实问答，每条包含：

1. 问题
2. 期望调用的工具（不要求顺序）
3. 标准答案要点
4. 不允许出现的内容（比如编造的指标名）

每次改 prompt 或加工具都跑一遍，记录工具选择准确率和答案质量。

## 十二、风险与坑

| 风险 | 影响 | 应对 |
|---|---|---|
| 模型编造工具名或参数 | 调用失败 | `registry.call()` 校验工具名和参数 schema，未知工具返回错误让模型重来 |
| 工具循环绕圈 | 延迟和成本失控 | `max_steps` 和 `max_tool_calls` 双上限 |
| 上下文被撑爆 | 模型报错或质量下降 | 结果截断，单次不超过 8000 字符 |
| 权限越界 | 查到不该看的数据 | 令牌绑定员工，参数不接受 `employee_id` |
| 延迟变高 | 前端等待时间长 | 前端 AI 超时已设 330 秒；批量场景改异步 |
| 现有测试失效 | CI 红 | `EchoModelClient` 同步实现工具调用，保持确定性 |
| 国内网络不稳定 | 模型调用超时 | 优先选国内模型，加超时和重试，失败走降级 |
| 没有评测集 | 无法判断变好还是变坏 | 阶段一之前先准备 20 到 30 条评测样本 |

## 十四、一句话总结

工具层不是把后端接口全暴露给模型，而是在 L2 加一层只读、窄权限、带截断和留痕的工具网关，在 L3 加一个有步数上限的调用循环。第一批只给问答和计划生成用，已经跑通的评分草稿链路先不动。
