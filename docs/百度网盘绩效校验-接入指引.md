## 二、你还差一步：授权（勾选网盘目录）

### 1. 打开授权链接

```
GET /v1/baidu/pan/authorize-url
```

或直接访问：

```
https://openapi.baidu.com/oauth/2.0/authorize
  ?response_type=code
  &client_id=0o0D3O3gdx7zRjWLjcp49TdsoTSZEYyi
  &redirect_uri=oob
  &scope=basic,netdisk
  &display=tv
```

⚠️ **`redirect_uri=oob`** —— 不需要公网域名，授权后页面直接显示授权码。

### 2. ⚠️ 授权页面上勾选要校验的网盘目录

**这是「自动拉取」的唯一入口。** 未勾选的目录应用读不到。

勾选后，目录会挂到 `/apps/绩效校验/` 下。

### 3. 提交授权码

```
POST /v1/baidu/pan/authorize
{ "code": "粘贴的授权码" }
```

⚠️ **code 只能用一次，10 分钟过期。**

后端会立刻做一次目录可读性探针，返回：

```json
{
  "authorized": true,
  "probe": {
    "ok": true,
    "path": "/apps/绩效校验",
    "scanned": 128,
    "hint": "目录可读"
  }
}
```

若 `probe.ok = false` 且 `errno = 42213`
⇒ **目录没勾对**，重新授权并勾选正确的目录。

## 三、之后全自动

```
定时任务（默认 6 小时）
  ↓ 自动用 refresh_token 换 access_token
  ↓ multimedia?method=listall&recursion=1
  ↓ 按上传时间（server_ctime）分日计数
  ↓ 写 baidu_pan_count 快照（同一窗口覆盖 ⇒ 幂等）
  ↓ 主管评分页可拉取实际值做比对
```

**access_token 30 天到期、refresh_token 10 年** —— 系统自动续期，
**不需要人工介入**。

## 四、两个百度特有的坑（已在代码里处理）

### 坑 1：`refresh_token` 只能用一次

官方原文：*"refresh_token 只支持使用一次，refresh_token 使用后失效，
下次刷新 Access Token 时需要使用上一次刷新请求响应中的 refresh_token"*

⇒ 刷新后**必须**把响应里的新 refresh_token 存回数据库。
不存 ⇒ 30 天后整条链路断掉。

**已处理**：`baidu_pan_service._save_tokens` 里
```python
if tokens.refresh_token:
    row.refresh_token = tokens.refresh_token
```
⚠️ 注意 `if` —— 刷新响应**可能不含**新 token，
那种情况要沿用旧的，不能清空。

**测试覆盖**：`test_ensure_access_token_refreshes_and_saves_new_refresh_token`、
`test_ensure_access_token_keeps_old_refresh_token_when_not_returned`。

### 坑 2：错误码不在 HTTP 状态码里

百度**一律返回 HTTP 200**，错误藏在响应体的 `errno` 字段。

只看 HTTP 状态码 ⇒ 把失败当成功 ⇒ 数据静默为空。

**已处理**：`_xpan_request` 强制检查 `errno`，非 0 抛
`BaiduPanError` 并翻译成人话。

## 三、目录限制（百度硬限制）

官方原文（2026-06-03 后创建的应用）：

> *"以下接口仅支持访问 `/apps/{appname}` 目录下的文件：
> `download` / `multimedia?method=listall` / `filemanager` /
> `precreate` / `meta` / `move`"*

⇒ **递归接口 `listall` 必须在 `/apps/` 下**。

⚠️ `file?method=list`（普通列目录）**不在**限制清单里，
但它**不递归**，只返回当前一层 —— 所以本实现走 `listall`。

### 配置

```env
BAIDU_PAN_APP_NAME=绩效校验     # ⚠️ 必须与百度开放平台的「应用名称」完全一致
BAIDU_PAN_WATCH_DIR=           # 相对 /apps/绩效校验 的子路径，如 /短视频成片
```

## 四、计数规则（可配置）

```env
# 只统计这些扩展名
BAIDU_PAN_COUNT_EXTENSIONS=mp4,mov,m4v,avi,mkv,flv,wmv
# 文件名含这些关键词的不计入（排除返工/废片）
BAIDU_PAN_EXCLUDE_KEYWORDS=返工,废片,废弃,作废,rework,_v2,_v3,副本
```

⚠️ **按上传时间（`server_ctime`）归日**，不是修改时间 ——
改过片的文件不会重复计数。

⚠️ 默认统计窗口 = **上个自然月**。当月没过完，数据必然不完整，
拿去核对会产生假异常。

## 五、API 清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/baidu/pan/status` | 授权状态 + 目录可读性探针 |
| GET | `/v1/baidu/pan/authorize-url` | 生成授权链接 |
| POST | `/v1/baidu/pan/authorize` | 提交授权码 → 换 token |
| POST | `/v1/baidu/pan/sync` | 立即取数（可指定窗口） |
| GET | `/v1/baidu/pan/counts` | 计数快照列表 |
| GET | `/v1/baidu/pan/batches` | 同步批次历史 |
| GET | `/v1/baidu/pan/sync/status` | 调度器运行态 |
| POST | `/v1/baidu/pan/compare` | 比对申报值 vs 实测值 |

⚠️ **所有端点都不返回 token** —— 只返回「是否已授权」和到期时间。

## 六、设计原则：不自动改分

```
网盘文件 ──> baidu_pan_count ──> 主管核对视图
                                     ↓
                        申报 6 条 / 实测 5 条
                                     ↓
                     "相差 1 条 —— 请核实后人工评定"
```

⚠️ **比对结果里没有任何分数字段** —— 由 `compare_with_report` 保证，
有测试 `test_compare_result_has_no_score_field` 守着。

理由与 `semantic_qc` / `distribution_qc` 一致：
**数据源只提供依据，判定权在人**。
差异可能是口径问题（返工片、跨月交付、命名规则），自动扣分会误伤员工。
