> 状态：设计规格，待代码实现

---

## 一、功能定义

### 为什么需要问答

现状问题：
- HR 每次都要登后台手工查一个部门的平均分
- 员工想知道自己的绩效完成多少，得去找主管问
- 主管要汇总下属的分数，得手工导表

### 问答能解决什么

✅ **员工可以问**：
- "我这月绩效是多少"
- "我和部门平均分差多少"
- "我这月哪项指标下降了"

✅ **主管可以问**：
- "我的某某员工完成多少"
- "我的团队本月平均分"
- "我团队有多少人达到 A 等级"

✅ **HR 可以问**：
- "某某部门本月平均分"
- "各部门优秀率对比"
- "这月 vs 上月绩效趋势"

### 不做什么

❌ 不生成数字（数字由规则引擎产出）
❌ 不修改任何数据
❌ 不绕过权限检查
❌ 不做跨期自动聚合（询问时才计算）

## 二、架构设计

### 2.1 三层问答架构

```
L1 交互层
  ├─ 后台 Web UI（HR/主管查询面板）
  └─ 飞书机器人（用户 @bot 提问，后续可加）
      │
      ↓ REST API
      │
L2 业务层（新增接口）
  ├─ GET /api/qa/query       ← 查询接口（只读）
  └─ POST /api/qa/ask        ← 问答接口（调用 AI）
      │
      ├─ 权限检查（谁能查什么）
      ├─ 数据范围隔离（PerformanceDataScopeService）
      ├─ 查询数据库（SELECT only）
      └─ 返回结构化数据
      │
      ↓ JSON
      │
L3 智能体层
  └─ /v1/agent/qa
      │
      ├─ 输入：结构化数据 + 提问语句
      ├─ 处理：理解 + 数据解释
      └─ 输出：自然语言回答 + 数据引用
```

### 2.2 数据流（一个查询示例）

```
员工问："我这月绩效完成多少"
  ↓ 后台收到请求 + 身份识别（从 token 拿员工 ID）
  ↓ 权限检查：employee_id 只能查自己
  ↓ 数据库查询：SELECT * FROM Score WHERE employee_id = ? AND period = current_month
  ↓ 返回 { "total": 78.5, "rating": "B", "components": {...} }
  ↓ AI 问答智能体接收这个结构化数据
  ↓ 生成回答："你本月绩效分数是 78.5 分，等级是 B（达成）。其中..."
  ↓ 返回给用户
```

## 三、权限模型（关键）

### 3.1 基础身份

从 `Bearer token` 里解出：
- `user_id` / `user_role` / `department` / `is_hr`
- 每个请求必须校验

### 3.2 查询权限矩阵

| 查询类型 | 员工 | 主管 | HR |
|---|---|---|---|
| **查自己的分数** | ✅ 可以 | ✅ 可以 | ✅ 可以 |
| **查下属的分数** | ❌ 不可以 | ✅ 可以（仅限直接下属） | ✅ 可以 |
| **查部门汇总** | ❌ 不可以 | ✅ 可以（仅限自己的部门） | ✅ 可以 |
| **查全公司汇总** | ❌ 不可以 | ❌ 不可以 | ✅ 可以 |
| **查历史数据** | ✅ 可以（自己的） | ✅ 可以（下属的） | ✅ 可以 |

### 3.3 数据可见性约束

某些字段**不同角色看到的内容不同**：

| 字段 | 员工看到的 | 主管看到的 | HR 看到的 |
|---|---|---|---|
| 分数 | ✅ 自己的 | ✅ 全部 | ✅ 全部 |
| 评语 | ✅ 自己的 | ✅ 下属的 | ✅ 全部 |
| 考勤异常 | ✅ 自己的 | ✅ 下属的 | ✅ 全部 |
| 个人自评 | ❌ 关闭 | ❌ 关闭 | ✅ 可选查看 |
| 主管评分过程 | ❌ 关闭 | ✅ 自己的 | ✅ 全部 |

> 说明：自评内容对下级可见性需要人事部确认（可选）。本设计默认关闭以保护主管的"中间想法"。

## 四、查询接口设计

### 4.1 GET /api/qa/query

**职责**：返回结构化数据，不调 AI

**请求**：

```json
{
  "type": "self_score",           // 查询类型
  "period": "2026-10",             // 月份（可选，默认当月）
  "query_params": {
    "employee_id": "..."           // 某些查询需要
  }
}
```

**查询类型枚举**：

```
self_progress           查自己本月的滚动进度（MetricValue）
self_result             查自己的月度最终结果（Score）
colleague_progress      查某下属的滚动进度
colleague_result        查某下属的最终结果
department_progress_summary    查部门的滚动进度汇总
department_result_summary      查部门的最终结果汇总
peer_comparison         查"我 vs 平均分"（月末结果）
trend                   查"这月 vs 上月"趋势
```

**关键区分**：

| | progress（月中任意时间可查） | result（月末）|
|---|---|---|
| 数据源 | MetricValue（原始指标值） | Score（主管确认的分数） |
| 可用性 | 全月都有（持续更新） | 仅月末有（月中为空）|
| 权重处理 | 基于"已出数权重"做降级计算 | 已确认，按 rubric 转换成得分 |
| 使用场景 | 员工月中自查进度 | 月末查最终成绩 |

### 4.3 POST /api/qa/ask

**职责**：接收自然语言问题，调用 AI，返回自然语言回答

**请求**：

```json
{
  "question": "我这月绩效怎么样",
  "context": {
    "period": "2026-10",           // 可选
    "scope": "self"                // self / colleague / department
  }
}
```

**流程**：

1. 权限检查 + 身份识别
2. 预处理：NLU 解析问题 → 映射到 `query_type` 白名单
3. L2 从身份推导查询范围（不信模型给的 ID）
4. 调用 `POST /api/qa/query` 获取结构化数据
5. 调用 `POST /v1/agent/qa` 让 AI 生成回答
6. 返回结构化回答

**响应**：

```json
{
  "answer": "你本月绩效分数是 78.5，等级是 B（达成）。比上月提高了 3.5 分，主要原因是 GMV 表现出色...",
  "data_quality": {
    "completeness": 0.95,
    "as_of": "2026-10-31",
    "degraded": false,
    "citations": [
      "Score.total",
      "MetricValue.gmv"
    ]
  },
  "follow_up_questions": [
    "我哪项指标最差",
    "这月 vs 上月趋势"
  ]
}
```

### 4.4 权限检查 + 模型输出不可信

**🔴 关键安全原则**：模型生成的 `query_type` 和 `employee_id` 都不可信，必须由 L2 从 HTTP 身份推导

**正确的流程**：

```python
def handle_qa_request(question: str, token: str):
    # 1. 从 token 解出可信身份
    user = get_current_user(token)  # user.id / user.role / user.department
    
    # 2. 模型只做 NLU 映射到白名单枚举（不能信值）
    query_type_enum = model.map_to_enum(question)
    # 输出示例：query_type_enum = "colleague_result" （仅枚举值）
    
    if query_type_enum is None:
        # 模型不确定，返回澄清问题而不是猜测
        return {"clarification": "请问你是在查 A 部门还是 B 部门？"}
    
    # 3. L2 从身份推导数据范围（模型绝不参与权限决策）
    if query_type_enum == "self_result":
        employee_id = user.id  # 自己的 ID
        
    elif query_type_enum == "colleague_result":
        # 不信模型给的下属 ID，从身份推导
        direct_reports = db.get_direct_reports(user.id)
        if not direct_reports:
            raise PermissionError("你没有下属可查")
        
        # 如果问题里有"张三"，在下属列表里做模糊匹配
        name_in_question = extract_name(question)  # L2 的工具函数
        target = fuzzy_match(name_in_question, candidates=direct_reports)
        if not target:
            return {"error": f"你的下属里没有'{name_in_question}'"}
        employee_id = target.id
    
    elif query_type_enum == "department_result":
        # 主管只能查自己的部门
        if user.role != MANAGER and user.role != HR:
            raise PermissionError("只有主管和 HR 能查部门聚合")
        department_id = user.department if user.role == MANAGER else query.department
    
    # 4. 现在权限已校验，安全地调用查询接口
    data = query_service.query(query_type_enum, employee_id)
    
    # 5. 调用 AI，传入已校验的结构化数据（AI 不再需要做权限决策）
    answer = ai_agent.qa(question, data)
    return answer
```

**模型的职责边界**：

| 场景 | 模型能做 | 模型不能做 |
|---|---|---|
| 理解问题 | ✅ "查我的分数" → `self_result` | ❌ 生成 employee_id |
| 澄清模糊 | ✅ "你的部门是 A 还是 B？" | ❌ 假设一个 department_id |
| 提建议 | ✅ "基于数据，你可以关注..." | ❌ 决策"你应该被考核吗" |

## 五、AI 层设计（智能体 qa）

### 5.1 职责边界

**可以做**：
- ✅ 解释数据（"这个分数是怎么来的"）
- ✅ 比较对比（"你比部门平均高/低多少"）
- ✅ 找规律（"你连续两月在这项下降"）
- ✅ 提建议（"根据数据，下月可以关注...")
- ✅ 澄清问题（"请问是查 A 部门还是 B 部门"）

**不可以做**：
- ❌ 生成数字（所有数字来自 L2）
- ❌ 修改数据
- ❌ 做权限决策（身份和范围由 L2 推导）
- ❌ 改变 query_type 的值（只能映射到白名单）
- ❌ 生成 employee_id / department_id（只能从问题里抽取候选值供 L2 模糊匹配）

## 五、隐私数据最小化（按智能体分别定义）

### 隐私原则

不同的智能体访问的数据不同 —— **一律最小化**，不用一句"脱敏了"概括。

### QA 智能体（问答）—— 数据最小化

只能看到结构化数据（不涉及 PII）：

```python
@dataclass
class QAInput:
    question: str              # 用户的问题
    query_result: dict         # 结构化数据
    # 包含：user_id (alias / code), score, components
    # 不包含：real_name, department, role_title
    
    user_role: str             # "employee" | "manager" | "hr"
    # 为了理解权限上下文，但仍为角色代码，不是姓名
```

示例：

```json
{
  "question": "我的分数怎么样",
  "query_result": {
    "user_id": "E001",         // ← 代码，不是 "张三"
    "score": 78.5,
    "components": [...]
  },
  "user_role": "employee"
}
```

### 填报辅导智能体（FillCoach）—— 必须访问自评文本

必须有自评内容才能追问，但要脱敏 + 留痕：

```python
@dataclass
class FillCoachInput:
    employee_id: str           # 代码，不是姓名
    self_review_text: str      # 必须有 —— 追问的前提
    form_schema: dict          # 表单定义
    
    # 审计信息（留痕）
    trace_id: str              # 审计 ID
    timestamp: str             # 何时脱敏
    deidentified_by: str       # 谁脱敏的（admin / system）
```

## 九、关键设计决策

### D1：小部门聚合隐私保护

**问题**：部门只有 2-3 人时，平均分能反推出个人信息。

**决策**：**少于 5 人的部门不显示平均值（k-匿名）**

```json
{
  "department_result_summary": {
    "total_employees": 3,
    "average_score": null,         // ← 隐藏
    "note": "样本过小，隐私保护中不显示平均分"
  }
}
```

### D2：跨月对比的数据源

**问题**：历史分数存不存？

**决策**：**存 `ScoreHistory` 表**（独立表，不是 Score 的历史字段）
- 每次重算分数前保存历史快照
- Q&A 可以查历史快照对比

> 注：表名统一为 `ScoreHistory`（不是 `Score.history`）。当前还未建库，待 P1 排期建表。

### D3：模型不可用时

**问题**：如果 AI 服务挂了怎么办？

**决策**：**仍然返回结构化数据，但不生成自然语言回答**
- 前端显示："AI 暂时不可用，以下是您的数据..."
- 用户可以自己看表格理解

### D4：敏感字段的加密

**问题**：分数、评语这些敏感数据怎么保护？

**决策**：**分层防御（待 IT 和法务确认具体要求）**

当前实现：
- ✅ 传输层：HTTPS（强制）
- ✅ 应用层：权限检查（HTTP Header 身份认证）
