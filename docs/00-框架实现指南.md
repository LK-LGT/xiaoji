## 三、AI 层

### 3.1 架构：BaseAgent + 六个实现

```
BaseAgent (base.py)
  ├─ __init__()          初始化：模型客户端、脱敏器、日志
  ├─ run()               执行管线：脱敏 → 调用 → 校验 → 重试 → 降级 → 留痕
  └─ fallback()          降级兜底
  
agents.py 继承 BaseAgent：
  ├─ FillCoach.run()     填报辅导
  ├─ Evidence.run()      证据校验
  ├─ Rating.run()        评级建议
  ├─ Comment.run()       总结写作
  ├─ Calibration.run()   校准提示
  └─ QA.run()            (新) 问答解读
```

### 3.2 BaseAgent 的执行管线

```python
class BaseAgent:
    async def run(self, input_data):
        """
        执行管线（模板方法）
        """
        # 1. 脱敏
        redacted = self.privacy_filter.redact(input_data)
        
        # 2. 调用模型（带重试）
        for attempt in range(3):
            try:
                result = await self.model_client.call(
                    messages=self.format_prompt(redacted)
                )
                break
            except Exception as e:
                if attempt == 2:  # 第 3 次还失败
                    result = self.fallback()
                    break
        
        # 3. Schema 校验
        validated = self.validate_schema(result)
        
        # 4. 反脱敏（如需要）
        output = self.privacy_filter.restore(validated)
        
        # 5. 留痕
        self.audit_log.record(
            input_hash=hashlib.sha256(json.dumps(input_data, sort_keys=True).encode()).hexdigest()[:32],
            output=output,
            status="ok" if not fallback else "degraded"
        )
        
        return output
```

### 3.4 智能体 vs 传统 LLM 调用

| 特性 | BaseAgent 方式 | 直接调用 LLM |
|---|---|---|
| 脱敏 | ✅ 自动 | ❌ 需手工处理 |
| 重试 | ✅ 指数退避 | ❌ 需手工循环 |
| 降级 | ✅ 自动兜底 | ❌ 需手工处理 |
| 日志 / 审计 | ✅ 自动记录 | ❌ 需手工埋点 |
| Schema 校验 | ✅ 自动 | ❌ 需手工验证 |

**加一个新智能体的最小代码**：

```python

    async def run(self, input_data):

        return await super().run(input_data)
    
    def format_prompt(self, redacted_data):
        return f"你的 prompt..."
    
    def validate_schema(self, output):
        # 返回 Pydantic model 或 dict
        return MyOutputSchema(**output)
    
    def fallback(self):
        # 降级时返回什么
        return {"status": "degraded", "data": "template"}

**主要函数**：

```python
def compute_score(
    record_id: str,
    metric_values: List[MetricValue],
    weights: Dict[str, float],
    rubric: Dict[str, RubricLevel]
) -> Score:
    """
    计算分数（唯一真值源）
    
    流程：
    1. 校验输入（不能有考勤）
    2. 按权重加权求和
    3. 查 rubric 定级
    4. 持久化到 Score 表
    5. 返回结果
    """
    
    # 1. 过滤：只取算分集
    scoring_values = [
        v for v in metric_values
        if v.source != "attendance"  # 决策②：考勤不进算分集
    ]
    
    # 2. 按 rubric 转换成得分（量纲转换）
    metric_scores = {}
    total = 0.0
    for v in scoring_values:
        # v.value 是原始值（比如 GMV=1250000），需要查表转成 0-100 的得分
        score_for_metric = lookup_score_in_rubric(v.metric_code, v.value)
        metric_scores[v.metric_code] = score_for_metric
        # 加权求和
        total += score_for_metric * weights[v.metric_code]
    
    # 3. 定级
    level = lookup_rating(total, rubric)
    
    # 4. 保存
    score = Score(
        record_id=record_id,
        total=total,
        per_metric_json=json.dumps(metric_scores),  # 各指标得分
        confirmed_at=now(),
        trace=build_trace(metric_values, weights)  # 可复算
    )
    db.add(score)
    db.commit()
    
    return score
```

> 注：等级在 `AssessmentRecord.confirmed_rating`，不在 Score 表
```

**不复算分数的方式**：

```python
def recompute_score(record_id):
    """
    重新计算分数（验证可复算性）
    """
    # 1. 查出当时的快照
    snapshot = db.query(ConfigSnapshot).filter_by(task_id=...).one()
    
    # 2. 查出这个员工的指标值
    metric_values = db.query(MetricValue).filter_by(record_id=record_id).all()
    
    # 3. 重新算
    new_score = compute_score(
        record_id=record_id,
        metric_values=metric_values,
        weights=snapshot.weights,
        rubric=snapshot.rubric
    )
    
    # 4. 对比旧分数（应该完全一致）
    old_score = db.query(Score).filter_by(record_id=record_id).one()
    assert new_score.total == old_score.total, f"分数不一致！{new_score.total} vs {old_score.total}"
    
    return new_score
```

### 4.2 配置管理（config_service.py）—— 决策③的物理实现

**三道保险缺一不可**：

```python
class ConfigService:
    def sync_config_from_feishu(self):
        """
        定时任务：从飞书多维表格读配置
        """
        # 1. 读入
        config = fetch_from_feishu()
        
        # 2. 校验（第一道保险）
        errors = self.validate_config(config)
        if errors:
            log_alert(f"配置校验失败：{errors}")
            return False  # 不生效
        
        # 3. 冻结快照（第二道保险）
        task = db.query(AssessmentTask).filter_by(
            status="in_progress"
        ).one()
        
        # 中途改配置不影响已评的任务
        snapshot = ConfigSnapshot(
            task_id=task.id,
            config_json=config,
            frozen_at=now()
        )
        db.add(snapshot)
        db.commit()
    
    def read_config_with_fallback(self, task_id):
        """
        读配置（带兜底）
        """
        try:
            # 尝试从飞书读
            config = fetch_from_feishu()
            self.validate_config(config)
            return config
        except Exception as e:
            # 失败时用上次快照（第三道保险）
            log_alert(f"配置读取失败，使用上次快照：{e}")
            
            last_snapshot = db.query(ConfigSnapshot)\
                .filter_by(task_id=task_id)\
                .order_by(ConfigSnapshot.frozen_at.desc())\
                .first()
            
            if last_snapshot:
                return json.loads(last_snapshot.config_json)
            else:
                raise ConfigNotAvailableError()
```

from fastapi import Depends
from app.domain.enums import UserRole

async def get_current_user(token: str = Header(...)) -> User:
    """从 token 拿身份"""
    payload = jwt.decode(token, SECRET_KEY)
    user = db.query(User).get(payload["user_id"])

async def require_hr(user: User = Depends(get_current_user)):
    """只有 HR 能调"""
    if user.role != UserRole.HR:
        raise ForbiddenError("Only HR can access")
    return user

async def require_manager_or_hr(
    user: User = Depends(get_current_user)
):
    """主管或 HR"""
    if user.role not in [UserRole.MANAGER, UserRole.HR]:
        raise ForbiddenError("Insufficient permissions")
    return user

## 六、常见问题

### Q1：分数突然变了，为什么？

**检查清单**：

1. 配置改了吗？→ 查 `ConfigSnapshot.frozen_at`
2. 指标值改了吗？→ 查 `MetricValue.updated_at`
3. 规则改了吗？→ 查 git diff `scoring.py`

**复现**：

```python
# 重新计算分数，对比旧值
new = scoring_service.recompute_score(record_id)
old = db.query(Score).filter_by(record_id=record_id).one()
print(f"新: {new.total}, 旧: {old.total}")
```

### Q2：AI 给出的建议和最终分数不一致？

**这是正常的**。AI 给的是建议（`RatingDraft`），分数由规则引擎算（`Score`）。主管可以不同意 AI 建议。

检查：
```python
# 查 AI 建议
rating_draft = db.query(RatingDraft).filter_by(record_id=record_id).one()
print(f"AI 建议: {rating_draft.level}")

# 查最终分数和各指标得分
score = db.query(Score).filter_by(record_id=record_id).one()
print(f"最终分数: {score.total}")
print(f"各指标得分: {json.loads(score.per_metric_json)}")  # ← 新增，包含各指标的转换后得分
```

### Q3：怎么知道分数是由哪些指标组成的？

**查 `Score.trace` 和 `per_metric_json` 字段**（可复算的完整记录）：

### Q4：为什么不能让 AI 改分数？

**四个理由**：

1. **审计**：分数改了，看不出是人改的还是 AI 改的
2. **可复算**：无法验证分数的计算过程
3. **离职**：如果 AI 改过分，后来员工要查历史分数，无法验证
4. **法律**：绩效影响薪酬，改分必须有人签字负责

### 异常处理

```python
# ✅ 好
try:
    config = fetch_from_feishu()
except FeishuAPIError as e:
    log_alert(f"飞书接口异常：{e}")
    config = load_fallback_config()
except ValueError as e:

try:
    pass
except:  # 太宽泛
    pass
```
