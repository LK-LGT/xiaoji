## 三、数据到底会发给模型什么（合规自查）

这是你拍板前最该看的部分。我在代码里逐层核对了：

### 第 1 层：`base.py::redact()` —— 模型调用**之前**
- 真实姓名 → 替换成 `"该员工"`
- 手机号 / 身份证 / 邮箱 → 掩码占位
- 只记录「移除了哪几类」，**不记录被移除的值**

### 第 2 层：`grounding.py::redact_obj()` —— 递归脱敏
- 敏感键（`mobile` / `phone` / `email` / `employeeNo`）值整体替换 `***`
- 文本里的手机号 / 身份证 / 邮箱正则打码

### 第 3 层：业务层 `privacy.redact_obj()` + 数据源白名单
- 考勤异常标 `usage=reference_only`，**不自动扣分**
- 数据源策略按角色过滤（`data_source_service`，默认不信任）

### 实际发出去的字段（按智能体）

| 智能体 | 会发什么 | **不会**发什么 |
|---|---|---|
| 证据校验 | 评语正文、指标上下文 | 分数 |
| 评级建议 | 指标 code / value / target / ratio / level_scale | **总分**（`RatingOutput` 里**根本没有 score 字段**） |
| 总结 | 员工别名、指标、证据 id + 摘要 | 真实姓名 |
| 问答 | 用户问题 + 工具返回的结构化数据 | —— |
| 校准 | 部门聚合统计 | 姓名、员工明细 |

### 三道「模型改不了分」的保险

1. **Schema 层**：`RatingOutput` 只有 `ratings` 字段，**物理上没有 score 字段**
2. **降级层**：模型挂了 → 规则引擎的结果照常出，流程不中断
3. **Grounding 层**（`grounding.py`）：模型给的引文必须在原文里**真实存在**，
   否则降级为 UNKNOWN —— 幻觉引文抓得到

> 💡 所以「用哪家模型」的**风险差异很小** —— 因为模型能碰的东西很有限，
> 且碰到分数的路径被堵死了。**真正影响合规的是「数据出不出内网」，
> 不是「哪家模型更聪明」。**

## 九、实施过程中踩到的三个真坑（Mock 测不出来，只有真跑才暴露）

> 这一节是本次实施最有价值的产出 ——
> **如果当初只写 Mock 测试，这三个坑一个都发现不了。**

### 坑 1 · DeepSeek 把 JSON Schema **本身**当成答案吐回来

**现象**：评级建议返回的是
```json
{"title":"RatingOutput","properties":{"ratings":{"type":"array",...}}}
```
而不是 `{"ratings":[...]}`。

**根因**：我把 Pydantic 生成的 `model_json_schema()` **原文**塞进了 system prompt。
但 Schema 里带 `title` / `properties` 这些**描述性字段**，
模型看到就以为「哦，你要的就是这个 schema」→ 原样吐回。

**修复**：不传 Schema 原文，改传**具体示例**：
```json
{"ratings": [{"dimension": "<字符串>", "level": "<字符串>", ...}]}
```
新增 `_schema_shape_hint()` —— 只取字段名与类型，生成示例值。

> 💡 **教训**：跨厂商时，「结构要求」用**示例**表达比用 **Schema** 表达可靠得多。

### 坑 2 · Schema 里的 `$ref` 不解析 → 示例全是 `null`

**现象**：改成示例后，`RatingOutput` 的示例是 `{"ratings": [null]}`。

**根因**：Pydantic 生成的 Schema 里，子模型是 `{"$ref": "#/$defs/RatingItem"}`，
我的 `_example_for_type()` 不认识 `$ref` → 直接返回 `None`。

**修复**：加 `$ref` 解析（支持 `#/$defs/...` 本地引用）。

### 坑 3 · `ratings: list[dict[str, Any]]` 是**不透明类型**，Schema 说不清里面有什么

**现象**：即使示例机制修好了，模型也不知道 `ratings` 的每一项该有哪些字段。

**根因**：`RatingOutput.ratings` 原本是 `list[dict[str, Any]]` —— 校验很宽松，
但也**提供不了任何形状信息**。

**修复**：新增 `RatingItem` 类型化模型
（`dimension` / `level` / `reason` / `evidence_ids`），
`ratings: list[RatingItem]`。

> ⚠️ **安全收益**：类型化后 `score` 字段**在类型层面就不可能存在** ——
> 以前靠「约定不要写 score」，现在靠「类型里根本没有这个位置」。
